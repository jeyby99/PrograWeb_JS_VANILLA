## Objectives

### General objective
Build a full-stack web application that connects a Spring Boot REST backend to a Vanilla JavaScript frontend, and consumes external public APIs.

### Specific objectives
- Implement a complete **CRUD** (Create, Read, Update, Delete) with Spring Boot and PostgreSQL.
- Expose a **REST API** with search by name.
- Build a **real-time search** page connected to our own backend (Page 1).
- Build a search page with a **4-second debounce** that consumes 6 endpoints from two external APIs (Page 2).
- Make the interface **responsive** using Bootstrap, Tailwind, CSS Grid, Flexbox and Media Queries.

## Scope

**Included**
- CRUD of entities (first name, last name, email) with Thymeleaf views.
- REST API at `/api/entidades` with CORS enabled.
- Page 1: real-time search against the project's own backend.
- Page 2: debounced search against the Rick and Morty API and PokéAPI.
- Responsive design for mobile, tablet and desktop.

**Not included**
- User authentication or authorization.
- Automated tests.
- Deployment to a production server (the app runs locally).

## Architecture

The project follows a **client-server architecture** with a **layered architecture** on the backend:

```
┌──────────────────────┐        HTTP / JSON        ┌───────────────────────────────┐
│  Frontend (Vanilla)  │ ────────────────────────► │  Spring Boot Backend          │
│  pagina1.html        │                           │                               │
│  pagina2.html        │                           │  Controller  (REST + MVC)     │
└──────────┬───────────┘                           │      │                        │
           │                                       │  Service     (business logic) │
           │ Fetch API                             │      │                        │
           ▼                                       │  Repository  (Spring Data JPA)│
┌──────────────────────┐                           │      │                        │
│  External APIs       │                           │  Model       (JPA Entity)     │
│  Rick and Morty      │                           └──────┼────────────────────────┘
│  PokéAPI             │                                  ▼
└──────────────────────┘                           ┌──────────────┐
                                                   │  PostgreSQL  │
                                                   └──────────────┘
```

- **Controller layer:** receives HTTP requests (MVC controller for Thymeleaf views and REST controller for JSON).
- **Service layer:** contains the business logic.
- **Repository layer:** database access through Spring Data JPA.
- **Model layer:** JPA entity mapped to a PostgreSQL table.
- **Page 1** talks to our own REST API. **Page 2** talks directly to the external APIs from the browser.

## Design Pattern

**Main pattern: MVC (Model-View-Controller)**, complemented by the **Repository pattern** and **Dependency Injection**.

**Why MVC?**
- It separates data (Model), presentation (Thymeleaf views and HTML pages) and request handling (Controllers), so each part can change without breaking the others.
- It is the natural pattern of Spring Boot web applications, which keeps the code organized and easy to maintain.

**Why the Repository pattern?**
- `EntidadRepository` hides the database access details. The rest of the application works with Java objects and never writes SQL directly.

**Why Dependency Injection?**
- Spring injects the services and repositories where they are needed, which reduces coupling between classes.

## Programming Paradigm

**Backend: Object-Oriented Programming (OOP).**
- Java is an object-oriented language, and the project models its domain with classes (`Entidad`), encapsulation (private attributes with getters and setters) and separation of responsibilities between classes.
- OOP fits Spring and JPA, where entities are objects mapped to database tables.

**Frontend: Event-driven and asynchronous programming.**
- The pages react to user events (typing, Enter key, button click).
- The Fetch API with `async/await` and `Promise.allSettled` lets the page request several endpoints at the same time without blocking the interface. If one API fails, the others still show their results.
- Array methods such as `map` and `filter` add a functional style when transforming the results.

## Features

### Backend
- Complete CRUD of entities (first name, last name, email) with Thymeleaf views.
- REST API at `/api/entidades` with search by name (`?query=`) and CORS enabled.

### Page 1 – Real-time search
Queries the project's backend on every keystroke and displays the records as cards.

### Page 2 – Debounced search with external APIs
Waits 4 seconds after the user stops typing (or Enter / Search button) and queries 6 endpoints:

| API | Endpoints |
|---|---|
| Rick and Morty | `character`, `location`, `episode` |
| PokéAPI | `pokemon`, `item`, `berry` |

Each result shows its description and image. On load, the page displays "Rick" characters by default.

## How to Run

**Requirements:** JDK 17, Maven and PostgreSQL.

1. Create the database in PostgreSQL:
   ```sql
   CREATE DATABASE "PrograWeb";
   ```
2. Set your username and password in `src/main/resources/application.properties`:
   ```properties
   spring.datasource.url=jdbc:postgresql://localhost:5432/PrograWeb
   spring.datasource.username=postgres
   spring.datasource.password=YOUR_PASSWORD
   ```
3. Run the application:
   ```bash
   mvn spring-boot:run
   ```
4. Open in the browser:
   - Home and CRUD: http://localhost:8080
   - Page 1: http://localhost:8080/pagina1.html
   - Page 2: http://localhost:8080/pagina2.html

Tables are created automatically thanks to `spring.jpa.hibernate.ddl-auto=update`.
